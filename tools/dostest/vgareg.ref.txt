# p_vgareg reference -- the VGA register file after a BIOS mode set, on 6.22/QEMU
#
# Source: tools/dostest/p_vgareg.asm on genuine MS-DOS 6.22 under QEMU (the
# msdos622 oracle). RE-CAPTURED 2026-09-23 (session 77) -- see below.
#
# ⛔⛔ THIS IS NOT GROUND TRUTH, AND THE FILE USED TO READ AS THOUGH IT WERE.
#   QEMU's video BIOS is the Bochs VGABIOS: modern, not period-correct firmware.
#   The companion vgareg.pcem.txt is the same probe under PCem with a REAL AMI
#   486 BIOS and a genuine IBM VGA ROM, and the two disagree on scores of bytes.
#   tools/vgaparity.py therefore scores only the bytes both oracles AGREE on and
#   reports the rest as DISPUTED -- because a byte where we "failed" against this
#   file alone may have been us matching real hardware.
#
# ⛔⛔ AND IT WAS RE-CAPTURED BECAUSE THE OLD CONTENT DID NOT REPRODUCE. The
#   mode07mono row was contaminated by the two hand-programmed cases that precede
#   it: Mode X leaves CR11 bit 7 set, write-protecting CR00-CR07, so the BIOS
#   mode set that followed could not do its job. The old row carried Mode X's
#   CR09; a fresh run of the same binary carried nine more of Mode X's registers.
#   p_vgareg now drops the protect and takes a clean mode-3 set first. A row that
#   does not reproduce is not evidence, and that one was being diffed across
#   hosts as though it were.
#
# ⚠ THE OLD PER-GROUP FORM IS GONE, and it was quietly lossy: its loader filled
#   only offsets 0 and 4-63, so Feature Control, Input Status 0 and the DAC Pixel
#   Mask were read as ZERO no matter what the file said. They happened to be 0x00
#   on this host, so nothing ever caught it. Everything is the whole 64-byte
#   buffer now.
#
# Layout: off 0 MiscOut, 1 FeatCtl, 2 InpStat0, 3 DACMask, 4..8 SR0-4,
#         9..33 CR00-CR18, 34..42 GR0-GR8, 43..63 AR00-AR14.

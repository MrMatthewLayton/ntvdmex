# Source: tests/probes/dos/p_vgareg.asm under PCem, config NTVDMEX-DOS622.cfg --
# an AMI 486 BIOS with a GENUINE IBM VGA ROM, running genuine MS-DOS 6.22.
# Captured 2026-09-23 (session 77) by scripts/pcemoracle.py.
#
# WHY A SECOND REFERENCE EXISTS. vgareg.ref.txt is the same probe against 6.22
# under QEMU, whose video BIOS is the Bochs VGABIOS -- not period-correct
# firmware. The two references disagree on 97 of 768 bytes, which is LARGER than
# the error the parity score was reporting against QEMU alone: so a byte where we
# "failed" may have been us matching real hardware, and a byte where we "passed"
# may have been us matching an anachronism. tools/vgaparity.py therefore scores
# only the bytes the two oracles AGREE on and reports the rest as DISPUTED.
#
# ⚠ THE MONO ROW IS NOT COMPARABLE ACROSS THESE TWO HOSTS, and the reason is
#   data rather than a defect. INT 10h AX=0007 leaves Miscellaneous Output = 0x66
#   on QEMU -- bit 0 CLEAR, the CRTC genuinely moved to 3B4 -- and 0x67 on PCem,
#   with a 40-column CRTC, i.e. its BIOS does not enter MDA-compatible mode 7 on
#   this machine at all. The probe now picks its port from MiscOut bit 0 rather
#   than from the mode number (which had made the whole PCem row read 0xFF), and
#   it clears CR11's write protect and takes a clean mode-3 set first (Mode X had
#   left CR00-CR07 protected, so the BIOS mode set could not do its job). Both
#   rows are now honestly captured and reproduce -- they are simply answers about
#   two machines that do different things for mode 7. PCem's is a 40-COLUMN
#   COLOUR setup: its BIOS does not enter MDA-compatible mode 7 here at all.
#
# Layout: off 0 MiscOut, 1 FeatCtl, 2 InpStat0, 3 DACMask, 4..8 SR0-4,
#         9..33 CR00-CR18, 34..42 GR0-GR8, 43..63 AR00-AR14.

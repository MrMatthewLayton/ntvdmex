**The third alpha of NTVDMEX.** NTVDMEX replaces `ntvdm.exe` on Windows XP SP3 (32-bit): MS-DOS
and Windows 3.x programs run on the real processor, each in its own window on the XP desktop.
This build makes NTVDMEX run properly on processors built from two dies, such as the Core 2 Quad,
and adds disk and CD images, a SoundFont synth and a choice of fullscreen resolution.

## What's new

- **Core 2 Quad and other two-die processors.** On these, v0.2.0-alpha could be slow and glitchy,
  getting worse the longer Windows had been running: games stalled, keys repeated, sound
  stuttered. The two halves of such a processor keep different time, and NTVDMEX trusted them
  both. Its clock no longer does, and it keeps itself on one half of the processor: *Settings >
  Machine > Keep on One CPU Die*, Auto by default. (#416, #417)
- **Faster Sharp and Bilinear filtering in fullscreen.** Sharp, the default, and Bilinear with a
  Scanlines or CRT effect are now drawn by the graphics card, as fast as Nearest. (#418, #227)
- **Scale3x, and rebuilt Scanlines and CRT effects** in *Settings > Video > Scaler*. (#158)
- **A floppy disk image as drive A:, and a CD image (ISO) as a CD-ROM drive**, in *Settings >
  Drives*, each with a drive letter you can choose. Your real drives stay as they are.
  (#240, #241)
- **A SoundFont synth.** *Settings > Audio > MIDI > SoundFont* plays MIDI music through a
  SoundFont (`.sf2`) file you choose, inside NTVDMEX's mixer.
- **Fullscreen at another display resolution**: *Settings > Video > Fullscreen Resolution*. (#331)
- **A text-mode font from a file you supply**: *Settings > Video > Text Mode Font*. (#321)
- **One video recording through screen-mode changes**, instead of one file per mode. (#357)
- **VESA 16-colour planar modes** (102h, 104h, 106h). (#326)
- **DirectSound output no longer drops sound.** It used to overwrite audio that had not been
  played yet. WinMM is still the default. (#234)
- Fixes: a Mode Y game (Mario) could close by itself (#358); leaving fullscreen now repaints the
  desktop (#332); DOS sees every file, including names with no short name; `DIR /W`, and `COPY`
  from a path, work; `status.bat` and `smoke.bat` work before the first run (#141).
- Windows 3.x: Character Map, WinHelp, Terminal and Write dialogs draw and close properly
  (#288, #318, #319, #320, #328, #283).

## Confirmed working

Run by hand on a real Windows XP SP3 machine with a Core 2 Quad Q9650 before this build was
promoted to release, with no noticeable graphics or sound glitches:

- **DOS:** Deadlite, Doom, Duke Nukem 3D, Hexen, Mario, QuickBASIC 4.5, Skyroads.

Earlier builds have also run ZAR, Lemmings, Heretic, QBasic, EDIT, MS-DOS's own `COMMAND.COM`,
and Windows 3.x Write, Sysedit, Paintbrush, Notepad and Calculator. Many other programs will not
work yet.

## Install

1. Download `ntvdmex-v0.3.0-alpha.zip`, check it against `SHA256SUMS`, and extract it anywhere.
2. Run `install.bat` as an administrator.
3. Close every DOS and 16-bit Windows program that is already running, or reboot.
4. Run `smoke.bat`: it should say PASS.
5. Run DOS and Windows 3.x programs the way you normally would.

`status.bat` says whether NTVDMEX or Windows' own NTVDM is in charge. **`uninstall.bat` puts
Windows' own NTVDM back**; installing changes one registry value and overwrites nothing. The
zip's `README.txt` has the details.

**Upgrading from an earlier alpha:** run `uninstall.bat` from the old folder, then install this
one. Your settings are kept.

Windows 3.x programs use XP's own 16-bit system files; bring the programs themselves.

## Before you install

- **Windows XP SP3, 32-bit, only.** It will not run on 64-bit Windows, which has no
  Virtual-8086 mode.
- **It replaces NTVDM for the whole machine** while installed: every DOS and 16-bit Windows
  program runs under NTVDMEX.
- **Windows XP has had no security updates since 2014.** Plenty of people still run it on a
  home network, behind a router with nothing exposed to the internet, and that's a reasonable
  choice, but it is a choice. Don't expose it to the internet directly, and give it access
  only to what it needs.
- This is an alpha. Expect programs that fail, look wrong or sound wrong.

## Known issues

- DOS programs always open their own window, rather than running inside the console that
  started them (#131).
- On one machine, DOS/4GW games ran very slowly. This build may fix it, but that has not been
  confirmed (#196).
- A DOS mouse driver such as `MOUSE.COM` loads, but the program using it gets no mouse movement.
  NTVDMEX provides the mouse itself, so none is needed (#411).
- Once in automated testing, Doom stopped in its first seconds; a related fault is fixed, but
  that one has not been shown to be the same (#358).
- 3DBench never shows a score (#242).

## Reporting a problem

[Open an issue](https://github.com/MrMatthewLayton/ntvdmex/issues/new/choose) with the program,
what you expected, what happened, and the log of that run: `debug\out\ntvdmhost.log` in the
folder you extracted. A security problem goes to [SECURITY.md](https://github.com/MrMatthewLayton/ntvdmex/blob/main/SECURITY.md).

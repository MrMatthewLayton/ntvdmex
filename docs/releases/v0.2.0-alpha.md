**The second alpha of NTVDMEX.** NTVDMEX replaces `ntvdm.exe` on Windows XP SP3 (32-bit): MS-DOS
and Windows 3.x programs run on the real processor, each in its own window on the XP desktop.
This build adds video capture and a built-in MIDI synth, and fixes ZAR's silent starts.

## What's new

- **Video capture.** *Tools > Capture > Capture Video* records the program's picture and all of
  its sound (sound effects, FM and MIDI music) to an AVI file. *Capture Screenshot* (Ctrl+F5)
  saves a picture. Both go to a `captures` folder beside NTVDMEX, named after the program and the
  time, for example `DOOM-2026-10-14_17-45-12.avi`. *Open Capture Folder* opens it. (#155)
- **Settings > Capture** (a new tab) chooses the folder and the video codec, picked from those
  installed on the PC, with quality and key-frame settings and the codec's own Configure window.
  *Restart running application when video capture starts* restarts the program when you start
  capturing, so a recording can begin at the very start. Recording never starts on its own.
- **A built-in MIDI synth**, now the default: MIDI music plays through Windows' own GS sound set,
  as before, but inside NTVDMEX's mixer, so it is in recordings and follows the volume and mute
  settings. *Settings > Audio > MIDI > Windows MIDI* is the previous behaviour. (#155)
- **ZAR's sound no longer fails at random.** Its sound-card detection was sometimes cut short.
  (#239)
- **Saving works in Windows 3.x Write and Sysedit.** (#327)
- The mouse sensitivity slider moves in steps of 10%. (#330)
- The Tools menu: *Limit CPU Speed*; *Capture Mouse* has gone (capture is automatic).

## Confirmed working

Run by hand on a real Windows XP SP3 machine before this build was promoted to release:

- **DOS:** Doom (sound effects, MIDI music through the built-in synth, mouse), ZAR (sound),
  Skyroads.
- **Video capture:** recordings of Doom and Skyroads, with picture, sound effects and music in
  step.
- **Windows 3.x:** saving in Write and Sysedit; Paintbrush, Notepad, Calculator.

Earlier builds have also run Duke Nukem 3D, Heretic, Lemmings, Mario, QuickBASIC 4.5, QBasic,
EDIT, MS-DOS's own `COMMAND.COM`, and more Windows 3.x programs. Many others will not work yet.

## Install

1. Download `ntvdmex-v0.2.0-alpha.zip`, check it against `SHA256SUMS`, and extract it anywhere.
2. Run `install.bat` as an administrator.
3. Close every DOS and 16-bit Windows program that is already running, or reboot.
4. Run `smoke.bat`: it should say PASS.
5. Run DOS and Windows 3.x programs the way you normally would.

`status.bat` says whether NTVDMEX or Windows' own NTVDM is in charge. **`uninstall.bat` puts
Windows' own NTVDM back**; installing changes one registry value and overwrites nothing. The
zip's `README.txt` has the details.

**Upgrading from v0.1.0-alpha:** run `uninstall.bat` from the old folder, then install this one.
If you saved settings with v0.1.0-alpha, your MIDI choice stays *Windows MIDI*; choose *Built-in
GS* in *Settings > Audio* to have music in recordings.

Windows 3.x programs use XP's own 16-bit system files; bring the programs themselves.

## Before you install

- **Windows XP SP3, 32-bit, only.** It will not run on 64-bit Windows, which has no
  Virtual-8086 mode.
- **It replaces NTVDM for the whole machine** while installed: every DOS and 16-bit Windows
  program runs under NTVDMEX.
- **Windows XP has had no security updates since 2014.** Do not run it on a network or with
  data you care about.
- This is an alpha. Expect programs that fail, look wrong or sound wrong.

## Known issues

- A program that changes screen mode while recording leaves one video file per mode (#357).
- Once in automated testing, Doom stopped in its first seconds with the built-in synth; it has
  not happened since (#358).
- Windows 3.x Write and Terminal dialogs can draw stale screen content (#328).
- Several Windows 3.x programs have drawing or closing defects (#162).
- Leaving fullscreen can leave the fullscreen picture on the desktop (#332).
- Lemmings' High Performance PC option shows the wrong palette and runs too slowly (#290).
- DOS programs always open their own window, rather than running inside the console that
  started them (#131).
- On some machines, DOS/4GW games have run very slowly; the cause is not yet known (#196).

## Reporting a problem

[Open an issue](https://github.com/MrMatthewLayton/ntvdmex/issues/new/choose) with the program,
what you expected, what happened, and the log of that run: `debug\out\ntvdmhost.log` in the
folder you extracted. A security problem goes to [SECURITY.md](https://github.com/MrMatthewLayton/ntvdmex/blob/main/SECURITY.md).

## [FACT] Telnet auto-capture is unreliable for the clean host; the manual gate is the truth
After the manual PASS, attempts to *also* capture `ntvdmhost.log` on disk via the automated telnet
path failed for harness reasons, not host reasons:
- `runwait-clean.bat`'s TFTP push had silently failed ("not recognized" when run), so the automated
  triggers never dropped `run.flag`.
- The logon **agent** (`vdmtrig.bat`) was **not running** this boot — a directly-dropped `run.flag`
  sat unconsumed for 20s. The reboot-free agent loop + `dostest.sh` are SPIKE-oriented (they publish
  the spike's `vdmhost.log`); the clean host needs the manual `gate-clean.bat` (or an agent that
  copies `ntvdmhost.log`).
- Net: **`gate-clean.bat` at the desktop is the reliable clean-host gate.** Off-VM (`run.sh` +
  `verify-memtest.sh`) remains the primary loop; the VM is a manual gate.

  (NTVDM VDD ABI / DirectDraw-on-XP / VGA+VESA emulation):
  - **Hybrid two-ABI model over one device bus:** a clean internal plugin ABI (`src/vdd/ntvdd.h` —
    claim ports / mem-window / interrupt, raise-IRQ, frame tick, flat-map, present) that all our own
    devices use, with explicit CPU-context register access (off-VM testable); plus a **deferred

## M3 slices 1b + 3 — I/O trap dispatch + DirectDraw presentation (later 2026-06-07)
- **Slice 1b (`b87b7f7`):** the event taxonomy was already recovered from the ntvdm disasm — IOPL-0
  IN/OUT `#GP` reflects as **event 2** with EIP at the faulting instruction — so instead of a passive
  probe I implemented the full dispatch and made the probe *confirm* it. `src/host/main.c`
  `host_try_io()` decodes the I/O instruction (E4-E7 imm8 / EC-EF DX / 0x66·0x67·0xF2·0xF3 prefixes /
  byte·word·dword) → `vdd_bus_io()` → advances EIP to resume; a genuine GP fault falls through to an
  enriched stop dump (event/status/info + bytes@CS:IP + VTIB event region). The host now stands up
  the bus + the real PIT VDD. `make-ioprobe.sh`/`ioprobe.com` (22 B): programs the 8254 over OUT,
  reads it back over IN, exits errorlevel 0x34 iff the trap→bus→PIT round-trip works. Builds
  KERNEL32-only. **Awaiting the manual VM gate** (`gate-clean.bat ioprobe.com`).
- **Slice 3 (`f831b9c`):** `src/vdd/present_ddraw.{h,c}` — pure-C DirectDraw 7 frame sink, windowed
  (primary+clipper, Blt-stretch to client) + exclusive fullscreen (640×480×32 flip chain, Blt+Flip),
  one index→ARGB conversion path, `DDERR_SURFACELOST` recovery. ddraw bound via GetProcAddress +
  inline IID (no `-lddraw`/`-ldxguid`). `tools/present_demo/present_demo.c` (+ CMake target) is a
  standalone animated test-pattern app (Alt+Enter/F11 fullscreen) — the visual gate on real XP.
  Imports kernel32+user32 only.
- **Now VM-gated, in priority order:** (1) `gate-clean.bat ioprobe.com` confirms the I/O trap; (2)
  run `present_demo.exe` in the VM to eyeball windowed + fullscreen blits. Both need the interactive

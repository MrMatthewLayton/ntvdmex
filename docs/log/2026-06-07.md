## [FACT] Telnet auto-capture is unreliable for the clean host; the manual gate is the truth
After the manual PASS, attempts to *also* capture `ntvdmhost.log` on disk via the automated telnet
path failed for harness reasons, not host reasons:
- `runwait-clean.bat`'s TFTP push had silently failed ("not recognized" when run), so the automated
  triggers never dropped `run.flag`.
- The logon **agent** (`vdmtrig.bat`) was **not running** this boot — a directly-dropped `run.flag`
  sat unconsumed for 20s. The reboot-free agent loop + `dostest.sh` are SPIKE-oriented (they publish
  the spike's `vdmhost.log`); the clean host needs the manual `gate-clean.bat` (or an agent that
  copies `ntvdmhost.log`).
- Net: **`gate-clean.bat` at the desktop is the reliable clean-host gate.** Off-VM (`run.sh` +
  `verify-memtest.sh`) remains the primary loop; the VM is a manual gate.

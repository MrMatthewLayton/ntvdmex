## [FACT] Known allocator gap: no merge-on-alloc
Building the test made an existing limitation explicit. `free()` coalesces **forward only**, and
`alloc()` (`AH=48`) never merges adjacent free blocks — but **real MS-DOS merges adjacent free
blocks during the allocation walk**. So two adjacent free blocks cannot jointly satisfy a request
that neither satisfies alone (real DOS would). Pinned deliberately as test **T9** so a future
`merge-on-alloc` fix is a visible, intentional change rather than a silent behaviour shift. This is
the next M2.4 *correctness* item (the happy paths are solid).

## Design note — why port, not refactor the spike
I ported the allocator into a standalone module rather than refactoring the just-committed spike to
share it. The spike is runtime-proven but can only be *re-run* on the flaky VM, so refactoring it
blind was the wrong risk. The port runs and is verified now, and becomes the clean basis for the
**M2.6** promotion, where `vdmhost` should `#include` `dos_mcb.h` and drop its inline copy (the two
are tagged SYNC until then).

## Live validation + dev-loop decision (later 2026-06-06)
- **M2.4 validated end-to-end on the real CPU.** Built a reboot-free loop (logon agent
  `vdmtrig.bat` watches a flag file; `runwait.bat` + `scripts/dostest.sh` drive it over one telnet
  session; `xp.py --wait` = real login probe), booted the VM, provisioned the agent, and ran a
  round: `memtest.com` executed through `vdmhost` in **V86** and returned **`MEMTEST PASS`, exit 0**.
  The trace matches the off-VM battery + dosbox-x exactly (alloc seg `0x1101`; oversized alloc
  refused with `max=0x8eff` after the post-free coalesce). **M2.4 exit criterion met.**
- **The telnet loop works but is a poor default.** Each round is ~1–2 min of silent flag-polling, and
  slirp (user-mode NAT) wobbled (`Slirp: Failed to send packet`); a confirming re-run died with
  `Connection reset` when the VM was closed mid-round. From outside it's indistinguishable from a
  hang — which is how it read to the user.
- **Decision (with the user): off-VM is the primary loop; the VM is a manual gate.** Routine
  allocator/DOS-logic work uses `tools/dostest/run.sh` + `verify-memtest.sh` (instant, reliable, no
  VM). Real-V86 confidence comes from `tools/dostest/gate.bat` run *inside* the VM, verdict pasted
  back. `scripts/dostest.sh` + the agent stay as an optional automated path.
- **Lessons:** (1) a silent multi-minute background round must stream progress and power the VM down
  cleanly afterward, or it looks dead; (2) XP `tftp` won't overwrite an existing read-only file —
  `del /f` first; (3) most M2.x validation needs no VM at all.

## Reading the three rows

**Row 1 — the version differs, deliberately.** We report `AX=1606` (DOS 6.22);
stock ntvdm reports `AX=0005` (DOS 5.0). That is our version knob's default, not
a defect, and it is the single most visible behavioural difference between the
two hosts.

**Row 2 — ★ NTVDMEX RUNS A PROGRAM STOCK NTVDM CANNOT.** Given 6.22's own
`MEM.EXE`, stock answers **"Incorrect DOS version"** and refuses, because it
claims to be DOS 5.0. We run it and print the report. This is the "ntvdm
superset" claim with evidence behind it rather than as an aspiration — and it
follows directly from row 1, which is why the version knob is not cosmetic.

**Row 3 — an EXEC'd child behaves the same on both.** Both hosts run the child
and return to the parent with CF=0. (`AX` differs and is not significant for
AH=4Bh; the probe's SIG says so.)
